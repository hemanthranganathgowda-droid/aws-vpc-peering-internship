AWS VPC Peering

A hands-on cloud networking internship project demonstrating private communication between two Amazon Virtual Private Clouds using VPC Peering, route tables, security groups, and connectivity tests.

Explore Architecture View Project Report ↗ View GitHub Repository

Project Overview

Understanding secure communication between isolated AWS virtual networks.

🎯 Objective

Establish private IP connectivity between two VPCs using AWS VPC Peering without routing application traffic through the public internet.

☁️ AWS Services

  • Amazon VPC
  • EC2 instances
  • VPC Peering
  • Route tables
  • Security groups

🔐 Security Focus

Apply network segmentation, private IP routing, least-privilege access rules, and controlled connectivity testing.

Testing & Results

Connectivity was verified before and after a controlled security-group change.

Test 1: Connectivity

ICMP ping tests between App-A (10.10.2.10) and App-B (10.20.1.10) succeeded in both directions.


PASS — 4 packets received; 0% packet loss.

Test 2: Security Restriction

The ICMP inbound rule allowing traffic from App-A was temporarily removed from App-B's security group.


EXPECTED RESULT — Ping failed.

Test 3: Recovery

The ICMP inbound rule was restored. Connectivity between the two private instances worked again.


PASS — Connectivity restored.

Key learning: A VPC Peering connection and correct routes are not sufficient on their own. Security-group rules must also permit the required traffic. Security groups act as virtual firewalls for associated network interfaces.
